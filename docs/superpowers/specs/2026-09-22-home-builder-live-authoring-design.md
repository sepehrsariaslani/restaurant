# سازنده صفحه اصلی و پیش‌نمایش زنده — طراحی اصلاحی

## هدف

ویرایشگر سایت باید مقدارهای خالی را همان‌طور که مدیر وارد می‌کند نگه دارد، مزیت‌ها را با فاصله و تصویر پس‌زمینه پشتیبانی کند، محتوای درباره‌ما را واقعاً قابل ویرایش کند، همه صفحه‌های اصلی را با کامپوننت‌های واقعی و هدر/فوتر زنده پیش‌نمایش دهد، و دکمه ذخیره تغییرات را مستقیماً روی سرور ثبت کند.

## معماری

- داده‌های مزیت در همان props بلاک نگه داشته می‌شوند و قرارداد هر ردیف به شکل `{ icon, image, title, description }` است. `icon` و `image` اختیاری هستند؛ نرمال‌سازیِ نمایش از trim کردن ورودیِ در حال تایپ جدا می‌شود تا فاصله انتهای متن از بین نرود.
- پیش‌نمایش بصری به یک کامپوننت زنده‌ی مستقل منتقل می‌شود که از `PublicHeader`، `HomePageRenderer`، `AboutUsPage`، `FaqPage`، `ProductGroupsPage` و `SiteFooter` موجود استفاده می‌کند. بنابراین تغییرات همان state فعلی را در صفحه واقعی نشان می‌دهند.
- ویرایشگر درباره‌ما همچنان از داده‌ی `aboutSections` استفاده می‌کند، اما گزینه‌ی `aboutSections` به اجزای صفحه درباره‌ما اضافه می‌شود و کنترل ویرایش در یک پنل قابل مشاهده قرار می‌گیرد. ذخیره محتوای سایت و تنظیمات تم مستقیماً API مدیریت را صدا می‌زند؛ layout هم از API layout خود استفاده می‌کند.

## رفتارهای قطعی

### Hero

- variant تمام‌صفحه حداقل `100svh` ارتفاع و عرض کامل container/viewport را می‌گیرد.
- در preview دسکتاپ و گوشی همان `HeroBlock` واقعی با CTA و تصویر فعلی رندر می‌شود.

### دسته‌بندی

- اگر `eyebrow` یا `title` در props وجود داشته باشد و مقدارش خالی باشد، خروجی نیز خالی می‌ماند؛ فقط نبودن کلید از مقدار پیش‌فرض استفاده می‌کند.
- انتخاب دسته محصولات را در همان صفحه باز می‌کند و در preview Builder نیز کارت دسته قابل کلیک است.

### مزیت‌ها

- فاصله‌های عنوان و توضیح هنگام تایپ حفظ می‌شوند.
- آیکن می‌تواند خالی باشد؛ در این حالت fallback آیکن نمایش داده نمی‌شود.
- برای هر ردیف امکان انتخاب تصویر با `ManagementImageDropzone` وجود دارد.
- تصویر به‌عنوان background کارت با overlay خوانا نمایش داده می‌شود.

### درباره‌ما و preview زنده

- گزینه‌ی «محتوای درباره‌ما» در صفحه درباره‌ما قابل انتخاب است.
- ویرایش/افزودن/حذف ردیف‌ها و تصویر هر بخش به همان state preview وصل است.
- preview صفحات خانه، درباره‌ما، FAQ، گروه محصولات و محصول، هدر و فوتر واقعی را با داده‌ی draft فعلی نمایش می‌دهد.

### ذخیره

- دکمه‌ی ذخیره در مراحل هویت، تم و محتوا payload فعلی را مستقیماً با API ذخیره می‌کند و پاسخ سرور را در state live/boot اعمال می‌کند.
- ذخیره layout از API layout انجام می‌شود.
- draft محلی فقط fallback آفلاین/بازخوانی است و نباید جای ذخیره سرور را بگیرد.

## خطا و سازگاری

- خطای ذخیره در همان صفحه با پیام فارسی نشان داده می‌شود و داده‌ی ویرایش‌شده از بین نمی‌رود.
- داده‌های قدیمی مزیت‌ها که فقط `icon/title/description` دارند بدون migration همچنان معتبر می‌مانند.
- اگر API preview محتوایی نداشته باشد، صفحه واقعی empty state خودش را نشان می‌دهد.

## تست و پذیرش

- تست نرمال‌سازی باید مقدار خالی آیکن، تصویر و فاصله‌های حفظ‌شده را پوشش دهد.
- تست source contract باید Hero تمام‌صفحه، preview زنده صفحات، editor درباره‌ما، uploader تصویر و ذخیره مستقیم را بررسی کند.
- `npm test` و `npm run build` باید بدون خطا اجرا شوند.
