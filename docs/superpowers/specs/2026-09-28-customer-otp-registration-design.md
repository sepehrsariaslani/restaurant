# طراحی ورود و ثبت‌نام مشتری با OTP موبایل

## هدف

ورود و ثبت‌نام مشتری باید با تأیید شماره موبایل انجام شود، ایمیل اختیاری باشد، مشتری جدید بعد از تأیید OTP اطلاعات پایه و رمز عبور را ثبت کند و مشتری واردشده بتواند رمز عبور خود را تغییر دهد.

## تصمیم‌های اصلی

1. مسیر اصلی مشتری از `restaurant.api.send_otp` و `restaurant.api.verify_otp` استفاده می‌کند و به لینک تأیید ایمیل وابسته نیست.
2. `verify_otp` برای شمارهٔ جدید Customer را بلافاصله نمی‌سازد؛ یک بلیت کوتاه‌عمرِ «شماره تأییدشده» صادر می‌کند.
3. `customer_register_password` بلیت تأییدشده را یک‌بار مصرف می‌کند، Customer و Website User را می‌سازد و ایمیل را فقط در صورت ورود ذخیره می‌کند.
4. SMS.ir Verify همچنان منبع ارسال OTP است، اما رویدادهای ارسال و تأیید OTP مشتری در `Mobile Login OTP Event` ثبت می‌شوند تا با OTP ورود Frappe یک گزارش واحد داشته باشند.
5. در صورت timeout یا خطای نامشخص شبکه، OTP cache حذف نمی‌شود؛ کاربر می‌تواند کدی را که provider پذیرفته است وارد کند و سیستم پیام را دوباره خودکار ارسال نمی‌کند تا هزینهٔ دوباره ایجاد نشود.
6. تغییر رمز عبور برای حساب دارای User به رمز قبلی نیاز دارد؛ حداقل طول رمز ۸ نویسه و تطبیق رمز جدید و تکرار آن اجباری است.

## جریان‌ها

### شمارهٔ موجود

`send_otp` → ارسال Verify → ثبت `sms_sent` → ورود کد → ثبت `otp_verified` → صدور `customer_token` و ورود.

### شمارهٔ جدید

`send_otp` → ارسال Verify → ورود کد → ثبت `otp_verified` → صدور `mobile_verification_token` → فرم نام، ایمیل اختیاری و رمز → مصرف بلیت → ساخت Customer/User → صدور نشست مشتری.

### تغییر رمز

پروفایل مشتری → رمز فعلی، رمز جدید و تکرار رمز → بررسی User متصل → تغییر رمز با API داخلی Frappe.

## داده‌های امنیتی

- OTP فقط در cache با عمر ۵ دقیقه ذخیره می‌شود و کد در لاگ ذخیره نمی‌شود.
- بلیت تأیید موبایل با کلید hash‌شده در cache و عمر ۱۰ دقیقه نگه‌داری می‌شود و پس از ثبت‌نام حذف می‌شود.
- payload لاگ SMS فقط مقدار جایگزین `OTP_CODE` را ثبت می‌کند.
- اگر provider پاسخ قطعیِ رد بدهد، OTP حذف می‌شود؛ اگر پاسخ نامشخص/timeout باشد، OTP باقی می‌ماند و نتیجه با وضعیت `delivery_pending` به UI برمی‌گردد.

## دامنهٔ تغییر

- `restaurant/restaurant/api.py`: چرخهٔ OTP، بلیت شمارهٔ جدید و لاگ رویدادهای مشتری.
- `restaurant/restaurant/customer_account.py`: تکمیل ثبت‌نام با بلیت موبایل و تغییر رمز.
- `restaurant/frontend/src/pages/CustomerLoginPage.vue`: حذف وابستگی UI به لینک ایمیل و اضافه‌کردن فرم پس از OTP.
- `restaurant/frontend/src/pages/CustomerProfilePage.vue`: فرم تغییر رمز.
- `restaurant/frontend/src/utils/api.js`: قرارداد API بلیت ثبت‌نام و تغییر رمز.
- `accounts/accounts/sms_ir_customer.py`: لاگ مشترک `Mobile Login OTP Event` و حفظ challenge در ارسال نامشخص.
- تست‌های Python و Node برای قراردادهای جدید.

## خارج از دامنه

- حذف endpoint قدیمی `customer_register_email`؛ برای سازگاری API باقی می‌ماند اما UI جدید آن را صدا نمی‌زند.
- تعریف یا تغییر شناسهٔ قالب SMS.ir در سایت؛ قالب موجود `login_otp` استفاده می‌شود و در صورت نبودن تنظیم معتبر، خطای قابل‌فهم نمایش داده می‌شود.
- باگ دیگری که در پیام کاربر ناتمام مانده است.
